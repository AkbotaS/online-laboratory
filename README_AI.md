# Online Laboratory: ИИ-наставник и оқу аналитикасы

## Запуск

1. Нужен Node.js 20 или новее.
2. Скопируйте `.env.example` в `.env`.
3. Задайте `ADMIN_USERNAME` и уникальный `ADMIN_PASSWORD` (не менее 12 символов). Этот аккаунт становится аккаунтом преподавателя при первом запуске. Если ключ OpenAI отсутствует, автоматическая проверка и аналитика продолжают работать, а наставник использует локальные общие подсказки.
4. Для ИИ-наставника задайте `OPENAI_API_KEY` в `.env`; не вставляйте ключ в клиентский JavaScript.
5. Из папки проекта запустите `node --env-file=.env server.mjs` и откройте `http://127.0.0.1:4173`. Не открывайте `index.html` через `file://`.

Преподаватель входит созданным аккаунтом и открывает отдельный пункт «Студенттер / Студенты» в левом меню. Там можно добавить одного студента, исправить ФИО, группу или логин, сбросить пароль, заблокировать/разблокировать и удалить аккаунт. Для массового добавления загрузите CSV с колонками «ФИО», «Группа», «Логин», «Временный пароль»; файл можно подготовить в Excel и сохранить как CSV UTF-8. Шаблон скачивается прямо из панели. Импорт принимает до 200 строк и показывает ошибки по строкам.

Логины могут содержать латинские буквы, цифры, точку, дефис и подчёркивание; пароль — от 10 символов. Временный пароль студент обязан сменить при первом входе; после смены он попадает в личную панель. Сброс администратором снова потребует смены временного пароля. Заблокированный аккаунт не может войти. Удаление аккаунта удаляет также связанные с ним учебные события и результаты.

## Авторизация и хранение

- Вход выдаёт случайную восьмичасовую сессию в `HttpOnly`, `SameSite=Strict` cookie. Клиент не выбирает роль при отправке событий: сервер берёт ID студента и группу из активной сессии.
- Пароли хранятся как соль и `scrypt`-хэш. Секреты преподавателя задаются только через окружение сервера.
- Учётные записи: `data/learning-analytics/users.json`; веса рубрики преподавателя: `data/learning-analytics/settings.json`; опубликованные работы и задания: `data/learning-analytics/curriculum.json`. Исходные учебные события: `data/learning-analytics/events.ndjson`. Рассчитанные баллы хранятся отдельно в `data/learning-analytics/measures.ndjson`. По умолчанию эти файлы переживают перезапуск Node-сервера в каталоге проекта. Для постоянного каталога на серверном хостинге можно задать `ONLINE_LAB_DATA_DIR`; сам каталог нужно хранить на постоянном закрытом диске. Групповые сводки вычисляются по запросу, а не сохраняются поверх исходных записей. Каталог `data/` исключён из Git — храните резервную копию и ограничьте доступ к папке проекта.
- Серверная маршрутизация `/api/learning/me` принудительно ограничивает студента его ID из сессии. Административные фильтры и `/api/admin/students` доступны только роли преподавателя. У студента нет доступа к панели администратора и результатам других пользователей. Неактивный аккаунт теряет доступ.
- При выдаче учебной программы студенту сервер удаляет из неё правильные ключи оборудования, этапов, микроскопа и контрольных вопросов. Проверка контрольных заданий и итоговая оценка выполняются сервером по сохранённым критериям; ответ API содержит только выбранный ответ, статус правильности и баллы, без эталонных вариантов. Для новых лабораторных ответов правильные критерии остаются в серверном `curriculum.json`.
- Редактируемые лабораторные работы, задания и настройки ЖИ-көмекші публикуются администратором через сервер и загружаются студентам при входе; изменения проверяются до 30 секунд. Браузерное хранилище остаётся локальным кэшем. Черновое состояние задания привязано к студенту и браузеру, а отправленные аналитические события сохраняются на сервере.
- Сессии хранятся в памяти процесса Node.js и завершаются при перезапуске сервера; сами события и аккаунты сохраняются на диске.

## Learning Analytics

Система регистрирует начало, продолжение и завершение лабораторной работы; значимые выборы оборудования, этапов, безопасность, отправленные ответы (только правильность и ID вопроса), ошибки, подсказки, исправления, длительность этапов, управление микроскопом, результат анализа и рассчитанные баллы. Движения мыши, экран, камера, текст свободного ответа и содержимое микрофотографий в журнал аналитики не отправляются. Перетаскивание стола микроскопа фиксируется одним событием по отпусканию указателя.

Браузер сохраняет события в очереди до отправки. События уходят пакетами, имеют уникальные ID для исключения повторного сохранения, а при недоступности сети остаются в локальной очереди. Сервер дополнительно ограничивает поля и длину значений. Аналитика не подменяет исходные события ответами ИИ. Сервер программно проверяет ответы по критериям преподавателя; ИИ не выставляет баллы. Итоговая оценка сохраняется отдельно от исходных событий.

Формулы и ограничения:

- Рубрика по умолчанию: оборудование — 15, порядок этапов — 30, безопасность — 15, микроскоп — 20, контрольные вопросы — 20 баллов. Преподаватель может изменить веса в административной панели; сумма всегда должна равняться 100. Баллы рассчитывает программная проверка сайта по критериям преподавателя, ИИ только объясняет ошибки и предлагает подсказки.
- Средний балл и распределение используют последнюю запись каждого студента по каждой лабораторной работе. Динамика показывает недельное среднее по зарегистрированным оценкам.
- Процент самостоятельного исправления = число уникальных ошибок, помеченных исправленными после OpenAI-подсказки, делённое на число уникальных ошибок с OpenAI-подсказкой × 100. Общие резервные подсказки считаются отдельно.
- Сравнение результатов с ИИ-поддержкой и без неё показывает средние баллы и количество попыток `n`. Оно описательное и не доказывает причинно-следственную связь.
- «Деморежим» создаёт только синтетические данные в памяти страницы, всегда помеченные как демонстрационные. Они не записываются на сервер и не выгружаются.
- Экспорт XLSX содержит листы с псевдонимизированными результатами и ограниченным набором исходных событий. CSV содержит события. Студент может выгрузить только собственные записи.

## ИИ-наставник

Сначала сайт проверяет действия по критериям. Для объяснений сервер использует OpenAI Responses API; ключ остаётся на сервере, запросы выполняются с `store: false`. Анализ выбранной микрофотографии предназначен только для педагогической обратной связи и не заменяет программные баллы. Если API не настроен или недоступен, студент видит локальную подсказку; в аналитике она помечается `fallback`, а не как ответ OpenAI.

## Ограничение публикации

Этот проект требует серверного маршрута и файлового каталога данных. Одной статической публикации HTML/JS недостаточно для авторизации, постоянного журнала и защищённых API. Для публичной эксплуатации нужно разместить Node-сервер за HTTPS и настроить постоянный закрытый диск либо перенести хранилище в защищённую базу данных. Не публикуйте `data/` и `.env`.

## Проверка аккаунтов

Запустите регрессионный сценарий из папки проекта: `node --test tests/student-accounts.test.mjs`. Он проверяет создание и хэширование паролей, обязательную смену временного пароля, блокировку/сброс, загрузку безопасной версии учебной программы, изоляцию аналитики и сохранение аккаунтов/баллов после повторного открытия хранилища.
